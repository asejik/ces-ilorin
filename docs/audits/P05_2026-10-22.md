### Details
- **P05-01**: every `<label>` on `/register` lacks `htmlFor` and does not wrap its input. Screen readers announce "edit text" with only the placeholder. Fix: give each field an `id` and `htmlFor` (the new `form-fields.tsx` makes this a one-place change) and mark required fields with `required` and `aria-required`. *Verify*: tab through the form with a screen reader (or the browser's accessibility tree) — each field should read its label.
- **P05-02**: add `aria-label="Rate 1 star"` etc. to the star buttons and use `role="alert"`/`aria-live="polite"` on error and result banners.
- **P05-03**: `loadGradebook` and `loadBroadsheet` only handle `res.success`; a failure (network, expired session, database) leaves `rows` empty and shows "No student records match…". Add an error banner with a "Try again" button.
- **P05-04**: plan requires password reset via email and instant deactivation (`PROJECT_PLAN.md` line 218–219). Neither exists. Minimum: a "Forgot password" link using Supabase's reset flow; document staff creation/deactivation in an admin guide.
- **P05-05**: `DEFAULT_AVAILABLE_QUIZZES` sets `is_open: true`, so if `getAvailableQuizzesAction` fails the student sees every quiz as OPEN, then gets a "session closed" error later. Show a "couldn't load quizzes — retry" state instead. At 360 px the select text is truncated ("— [OP").
- **P05-06**: add `not-found.tsx` with the school branding and a Home link; make the certificate error page's link context-aware.
- **P05-09**: ask the client whether the attendance screen should list only the two mandatory classes (plus optional lessons) — see "Questions".

## 7. Testing strategy — draft smoke scenarios (for your approval)
Run against a **staging Supabase project** with a seeded staff account:
1. **Register**: fill all required fields + photo → success page shows a matric number → welcome email (captured by a mail sink) arrives; negatives: missing consent, duplicate email within 60 s.
2. **Quiz**: staff opens a quiz and sets a PIN → student enters matric + PIN → answers 5 questions → score shown; second attempt blocked; wrong PIN rejected; **anon API call cannot read PINs**.
3. **Attendance**: check-in needs the class code; duplicate blocked; Sunday-cohort check-in appears on the Sunday broadsheet.
4. **Gradebook**: staff login → override a score with a reason → value + "M" shown; override above the quiz maximum is refused; toggling Sunday attendance persists in the Sunday semester.
5. **Broadsheet**: totals, honours, status for seeded edge cases (49.9, 50, 74.9, 75, 85); Excel downloads and opens; certificate issue + print page.
6. **Security smoke**: anon REST insert into `ces_students` is refused; passport URL without a signature returns 403; `/admin` redirects when logged out; 100 concurrent quiz submissions finish with zero errors (replaces the current load test).
