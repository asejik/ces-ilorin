## Executive Summary

A comprehensive pre-launch application security audit was performed on the Citizens Elementary School (CES) platform. The application demonstrates solid defensive engineering in several critical areas:
- **Zero Raw SQL / Parameterized Queries**: All database interactions use Supabase Query Builder, completely eliminating SQL injection vectors.
- **Answer Key Protection**: Server-side scoring runs exclusively in isolated Node.js server environments; candidate-facing API payloads explicitly strip `correct_option_index`.
- **Secret Hygiene in Git**: `.env.local` is strictly excluded from version control; git history inspection confirms zero committed credentials or active API tokens.
- **Robust Security Headers**: Active CSP, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Permissions-Policy` headers deployed.

However, the audit revealed a **CRITICAL authorization vulnerability**: administrative routes under `/admin/*` and administrative Next.js Server Actions lack server-side authentication validation. Because administrative Server Actions utilize `createAdminClient()` (which runs with the PostgreSQL `service_role` superuser key, bypassing Row Level Security), any unauthenticated client can read student records, dump all curriculum exam PINs, arbitrarily alter student grades, or toggle assessment session availability. 

Additionally, file uploads currently trust the browser's MIME type and unsanitized file extensions, creating potential stored XSS exposure on the assets bucket.

These vulnerabilities must be remediated and verified before deploying to production or admitting real students.

1. **Curious / Dishonest Candidate**: Enrolled student seeking early access to examination questions, Session PINs, or seeking to inflate their scores to achieve a "Distinction" classification ($\ge 85\%$).

## Audit Findings & Evidence

### Section 1: Authorization and Data Access (Highest Priority)

#### [Finding 1.1 — CRITICAL] Unauthenticated Access to Administrative Routes and Server Actions (RLS Bypass via `createAdminClient`)
- **Category**: Broken Access Control (OWASP A01:2021)
- **Files Affected**:
  - [`src/lib/supabase/middleware.ts`](file:///home/asejik/projects/ces/src/lib/supabase/middleware.ts)
  - [`src/actions/gradebook.ts`](file:///home/asejik/projects/ces/src/actions/gradebook.ts)
  - [`src/actions/broadsheet.ts`](file:///home/asejik/projects/ces/src/actions/broadsheet.ts)
  - [`src/actions/assessment.ts`](file:///home/asejik/projects/ces/src/actions/assessment.ts)
  - [`src/actions/attendance.ts`](file:///home/asejik/projects/ces/src/actions/attendance.ts)
  - [`src/app/admin/gradebook/page.tsx`](file:///home/asejik/projects/ces/src/app/admin/gradebook/page.tsx)
  - [`src/app/admin/quizzes/page.tsx`](file:///home/asejik/projects/ces/src/app/admin/quizzes/page.tsx)
  - [`src/app/admin/broadsheet/page.tsx`](file:///home/asejik/projects/ces/src/app/admin/broadsheet/page.tsx)
  - [`src/app/admin/attendance/page.tsx`](file:///home/asejik/projects/ces/src/app/admin/attendance/page.tsx)
- **Description**:
  1. **Route Level**: Next.js middleware ([`src/lib/supabase/middleware.ts`](file:///home/asejik/projects/ces/src/lib/supabase/middleware.ts)) refreshes the session cookie but does not enforce route protection on `/admin/*`. Unauthenticated users can load the full admin client application bundles directly.
  2. **Action Level**: All administrative Server Actions (`getCohortGradebookAction`, `overrideStudentScoreAction`, `getTeacherQuizzesAction`, `updateQuizSessionAction`, `getBroadsheetAction`, `batchIssueCertificatesAction`, `getAttendanceFeedbackAction`) instantiate `createAdminClient()` using `SUPABASE_SERVICE_ROLE_KEY`. None of these actions check `supabase.auth.getUser()` or verify that the caller exists in `ces_staff_profiles`.
- **Attack Scenario**:
  1. An unauthenticated attacker visits `http://localhost:3000/admin/quizzes`.
  2. The page component calls `getTeacherQuizzesAction()`.
  3. The server action executes `createAdminClient()`, which queries `ces_quizzes` using the service role key and returns all quizzes, including their active `session_pin` values (e.g., `REV77`, `PWR01`).
  4. The attacker opens the browser devtools or invokes `updateQuizSessionAction({ quizId: '...', sessionPin: 'LEAKED', isOpen: false })` via an unauthenticated POST request, successfully locking all students out of an ongoing examination.
  5. The attacker visits `http://localhost:3000/admin/gradebook`, calls `overrideStudentScoreAction({ studentId: '...', quizId: '...', newScore: 100, reason: 'Arbitrary' })`, and updates grades across the school database with zero authorization checks.
- **Safe Self-Test**:
  Open an incognito browser window (clearing all cookies). Run:
  ```bash
  curl -I http://localhost:3000/admin/gradebook
  ```
  Notice it returns `HTTP/1.1 200 OK` instead of `307 Redirect` to `/login`.
- **Remediation**:
  1. **Enforce Middleware Route Protection**: Update `src/lib/supabase/middleware.ts` to redirect any request to `/admin/*` lacking a verified `user` session to `/login?redirect=${pathname}`.
  2. **Create Server-Side Staff Guard**: Implement `requireStaffUser()` in `src/lib/auth/guard.ts` using `createClient()` (cookie-based). Verify that `user` is non-null and that a corresponding active record exists in `ces_staff_profiles`.
  3. **Guard All Admin Actions**: Call `await requireStaffUser()` at the start of every administrative action in `src/actions/*`.
  4. **Seed Administrator**: Link existing Supabase Auth user `admin@citizens.church` (`7b0bd1dc-9def-4aed-af93-da32ba3bd503`) into `ces_staff_profiles` with `super_admin` role.

#### [Finding 4.1 — LOW] Unescaped HTML Interpolation in Transactional Welcome Email
- **Category**: Content Injection / Email Spoofing
- **File Affected**: [`src/lib/email.ts`](file:///home/asejik/projects/ces/src/lib/email.ts#L79)

- Supabase SSR cookie wrappers set `SameSite=Lax` on all session tokens.

### Section 5: Business Logic Abuse

#### [Finding 5.1 — MEDIUM] Assessment Submission Endpoint Does Not Re-Validate Active Session PIN
- **Category**: Incomplete Authorization / Workflow Bypass
- **File Affected**: [`src/actions/assessment.ts`](file:///home/asejik/projects/ces/src/actions/assessment.ts#L332)
- **Description**: `verifyAssessmentAccessAction` enforces the Session PIN before returning questions to the client. However, `submitAssessmentAction` only validates `matricNo`, `quizId`, and `quiz.is_open`. If a student receives question IDs and answer options from a peer, they can submit their assessment directly via an automated POST without possessing the teacher's active in-class PIN.
- **Attack Scenario**:
  1. Student A takes the "Righteousness" quiz in class using the active PIN.
  2. Student B is absent from class but receives the quiz ID and answer list from Student A.
  3. Student B calls `submitAssessmentAction({ matricNo: 'CES/ILR/26I02', quizId: '...', answers: { ... } })`.
  4. The server grades and records the score, bypassing the teacher's in-class attendance prerequisite.
- **Safe Self-Test**: Call `submitAssessmentAction` via code or curl with answers, omitting `sessionPin`. The action evaluates and commits the score to `ces_student_assessments`.
- **Remediation**: Add `sessionPin` to `assessmentSubmissionSchema` and verify `(quiz.session_pin || '').trim().toUpperCase() === sessionPin.trim().toUpperCase()` in `submitAssessmentAction` before grading.

#### [Finding 5.2 — MEDIUM] Predictable Matriculation Numbers Enable Candidate Impersonation / Denial of Service
- **Category**: Identity Spoofing in Zero-Account Model
- **Files Affected**: [`src/actions/assessment.ts`](file:///home/asejik/projects/ces/src/actions/assessment.ts), [`src/actions/attendance.ts`](file:///home/asejik/projects/ces/src/actions/attendance.ts)
- **Description**: Matriculation numbers follow a sequential pattern (`CES/ILR/26I01`, `CES/ILR/26I02`, ...). Because candidates authenticate with only their Matriculation Number and the shared in-class Session PIN, any candidate in the room can submit an empty test under a classmate's matric number before that classmate begins. Because `ces_student_assessments` enforces a unique constraint on `(student_id, quiz_id)`, this locks the victim out with a duplicate submission error.
- **Attack Scenario**:
  1. Malicious student in class knows classmate John Doe is assigned `CES/ILR/26I04`.
  2. The malicious student submits a 0-score assessment under `CES/ILR/26I04`.
  3. John Doe logs in and is blocked with: "You have already completed this assessment... recorded score is 0 / 5."
- **Safe Self-Test**: Submit a quiz with another student's matric number. The victim is subsequently locked out of that quiz.
- **Remediation**:
  1. Mitigate immediate impact through the already implemented **Teacher Manual Score Override** in `/admin/gradebook` with required audit reason.
  2. Enhance intake verification by prompting candidates for a second identifier (e.g., verifying their registered phone number or surname initial) before opening quiz sessions.

### Section 8: Files and Storage

#### [Finding 8.1 — HIGH] File Upload Validation Relies on Client-Supplied MIME Type & Uses Unsanitized Extension
- **Category**: Insecure File Upload (OWASP A04:2021)
- **Files Affected**:
  - [`src/lib/validation/registration.ts`](file:///home/asejik/projects/ces/src/lib/validation/registration.ts#L50)
  - [`src/actions/register.ts`](file:///home/asejik/projects/ces/src/actions/register.ts#L130)
- **Description**:
  1. In `src/lib/validation/registration.ts`, `validatePassportFile` validates `file.type`, which is an unauthenticated client-controlled HTTP header (`Content-Type`).
  2. In `src/actions/register.ts`, the file extension is extracted directly from the user's file name: `const fileExt = passportFile.name.split('.').pop() || 'jpg';`.
  3. The file is uploaded to `ces-assets` under `passports/${matricNo}.${fileExt}`. If an attacker uploads an HTML or SVG file with `Content-Type: image/jpeg` and filename `payload.html`, the file is stored as `passports/CES_ILR_26I01.html`.
  4. Visiting the public Supabase storage URL directly executes the HTML/JavaScript in the browser.
- **Attack Scenario**:
  1. Attacker crafts a registration request with a malicious HTML payload containing a script.
  2. Attacker sets multipart `filename="avatar.html"` and `Content-Type: image/png`.
  3. Validation passes. Storage writes `passports/CES_ILR_26I01.html`.
  4. When an administrator or user views the passport photo link, the script executes on the storage domain.
- **Safe Self-Test**:
  Submit a test upload with `filename = 'avatar.html'` and spoofed MIME type `image/jpeg`. Observe that `filePath` uses `.html`.
- **Remediation**:
  1. **Strict Extension Allowlist**: Derive file extension strictly from validated MIME types:
     ```ts
     const MIME_TO_EXT: Record<string, string> = {
       'image/jpeg': 'jpg',
       'image/png': 'png',
       'image/webp': 'webp',
     };
     ```
  2. **Magic Bytes Validation**: Inspect the first 4 bytes of the uploaded file buffer on the server:
     - JPEG: `FF D8 FF`
     - PNG: `89 50 4E 47`
     - WebP: `52 49 46 46` (RIFF)
  3. Reject any file whose magic bytes do not match the declared MIME type.

## Actionable Remediation Plan

To bring the platform into full production readiness compliance, the following 4 defensive patches should be executed:

1. **Authorization Patch (F-01)**:
   - Update `src/lib/supabase/middleware.ts` to redirect unauthenticated visitors from `/admin/*` to `/login`.
   - Create `src/lib/auth/guard.ts` with `requireStaffUser()`.
   - Enforce `await requireStaffUser()` in all administrative Server Actions across `gradebook.ts`, `broadsheet.ts`, `assessment.ts`, and `attendance.ts`.
   - Seed `admin@citizens.church` into `ces_staff_profiles`.
2. **File Upload Hardening Patch (F-02)**:
   - Update `validatePassportFile` and `registerStudentAction` to validate buffer magic bytes and strictly assign extension based on validated image MIME type.
3. **Assessment PIN Re-Validation Patch (F-03)**:
   - Add `sessionPin` to `assessmentSubmissionSchema` and re-verify in `submitAssessmentAction`.
4. **Login Redirect & Email Escaping Patch (F-05, F-06)**:
   - Point login success redirect to `/admin/gradebook`.
   - Escape HTML entities in transactional email template.
